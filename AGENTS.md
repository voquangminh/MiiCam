# AGENTS.md

Alternate firmware for the Xiaomi Chuangmi 720p IP camera (Grain Media GM8136S SoC). Everything cross-compiles to `arm-unknown-linux-uclibcgnueabi` (ARMv5TE, uclibc, gcc 4.4.0) and is bundled onto an SD card (`sdcard/`) flashed into the camera. There is no test suite; verification = cross-compile + run on a real camera.

## Build system

- Canonical full build is Docker-based: `./manage.sh --shell` (interactive build env), `--build` (runs `make images clean`), `--build-docker`, `--all`. Toolchain is expected at `/usr/src/arm-linux-3.3/toolchain_gnueabi-4.4.0_ARMv5TE/usr/bin` inside the container.
- Top-level `Makefile` builds everything (`all`), packs the SD image (`images` → `MiiCam.zip`/`MiiCam.tgz`), and `clean` wipes `src/`, `prefix/`, `build/`, `tools/bin`, `tools/lib/*.so`, **and `sdcard/firmware/bin` + `sdcard/firmware/lib`** (committed binaries get deleted too — repopulate with `make install`). `all` = every `tools/lib` shared lib, every `tools/utils` binary (incl. `take_snapshot`/`take_video`), website, `sdcard/config.cfg`, and the whole third-party package list. The custom daemons NOT in `all` are `aac_play` (`make build/aac_play`; CI `build-aac-play.yml` compiles it directly), `rtspd2MP` (built only via `make build/rtspd2MP` / CI `build-rtspd.yml`), and `miio_avstreamer` (`make build/miio_avstreamer`).
- Third-party source tarballs are downloaded into `src/` (gitignored) per `tools/dev/sources.json` by `tools/dev/download-sources.py`; each `tools/make/*.mk` downloads/extracts/builds one package into `prefix/`.
- To build only a specific target: `make build/<target>`. The only `build/*` rules are the eight custom daemons — `rtspd`, `rtspd-v5`, `rtspd2MP`, `aac_play`, `rtsp_audio_in`, `tracking`, `onvif_server`, `miio_avstreamer`; the utils/`tools/lib` libs have NO `build/*` rule (they build via `all`/`utils`/`libs`, e.g. `make utils`).
- `tools/miio_avstreamer/miio_avstreamer.c` → `tools/bin/miio_avstreamer` (`make build/miio_avstreamer`) — local reimplementation of the Mijia-cloud vendor daemon (`miio_avstreamer`, replaced the closed TUTK `libIOTCAPIs`/`libAVAPIs`/`libRDTAPIs` stack; the code is derived from the `chuangmi-v5-dump` binary but runs a local media stream instead of the cloud). Single self-contained file (own JSON parser/builder, AES-128-CBC, mqtt via subprocesses, MP4 mux) — the only non-`tools/lib` dependency is `gmlib` + the vendored `algorithm/capture_motion_detection.c` (reached via `-I$(RTSPDDIR)`). Local stream server binds `MIIO_STREAM_PORT` (8601) and frames each media payload `[0x52 0x49][type][len BE32]`, `type` in `V`=H264, `A`=AAC/ALAW, `S`=snapshot JPEG, `M`=JSON meta; a JSON-RPC control socket on `127.0.0.1:MIIO_RPC_PORT` (8686) exposes `get_prop`/`set_power`/`set_flip`/`set_watermark`/`set_light`/`set_alarmsensitivity`/`set_night_mode`/`set_motion_record`/`set_motion_snapshot`/`set_motion_tracking`/`sd_storge`/`sd_format`/`saveVideo`/`saveVideoNow`/`deleteVideo`/`get_video_list`/`playback`/`ptz`/`correct_ptz`/`reboot_device`/`upload_log`/`HandHouseKeep_thiefAlarm`. Thread/function names mirror the vendor: `thread_VideoFrameData`, `thread_AudioFrameData`, `thread_RecordMp4`, `thread_PlaybackFile`, `thread_MotionDetect` (+ `motion_alarm_start`), `take_snapshot`, `thread_SDCardCheck`, `thread_SysMonitor`, `thread_AudioPlayer` (RTP→`/tmp/sound_fifo`→renderer), `thread_MQTTSub`. Booleans come from the config keys `MIIO_*`/`MOTION_*` in `config.cfg`. NOT wired into `all` — build with `make build/miio_avstreamer` (CI `build-miio-avstreamer.yml`, push-triggered on `tools/miio_avstreamer/**`/`Makefile`, force-adds and commits `tools/bin/miio_avstreamer`). **Mutually exclusive with the whole RTSP stack**: the GM8136 gmlib graph is single-instance, so it must NOT run alongside `rtspd`/`rtsp_audio_in`/`aac_play` (they fight over capture/encoder/audio-render binds) and it makes `S65onvif`/web control useless (those target `/tmp/rtspd.ctrl`). To run on a camera instead of rtspd: set `ENABLE_RTSP=0` in config.cfg (`.boot.sh` then skips `S60rtsp`) and start `/tmp/sd/firmware/bin/miio_avstreamer` manually (or via a custom init script). Config compatibility is intentional (reads the same `RTSP_WIDTH/HEIGHT/FRAMERATE/BITRATE/BITRATE_MODE/GOP` + `MOTION_*` keys as rtspd). On-camera smoke test: `nc <camera> 8601` should show `RI`+`V`/`A` frames, and JSON-line RPC on `127.0.0.1:8686` (e.g. `printf '{"id":1,"method":"status"}\n' | nc 127.0.0.1 8686`). Verified on-camera (Sep 2026, exclusive run with rtspd/onvif/tracking stopped): `gm stream init OK: 1280x720@30 1024kbps gop=15 mode=2 audio=aac/16000`, 8601 streams RI-framed H264 (start codes `00 00 00 01 67/65/41`), `get_prop`/`set_flip`/`saveVideoNow` work — `saveVideoNow` writes a **valid MP4** (`ftyp isom`+`moov`+`mdat`, `record done: ... (604 video, 314 audio samples)`) to `RECORDED_VIDEOS/YYYY/MM/DD/`. Known platform behaviour/caveats: (a) **snapshot is broken on this camera** — `gm_request_snapshot` returns `-4` (timeout) here, and stock `rtspd` logs the identical `Timeout while waiting for snapshot data`; it's a gmlib/platform limitation, not a miio bug (snapshot in miio requests a keyframe first and retries once); (b) the gmlib **`keyframe` flag is unreliable** — SPS/PPS are extracted by scanning every received frame with `nal_unit_type = byte & 0x1f` (a prior `>>5 & 0x1f` broke both extraction and IDR detection); the encoder is warmed with two `gm_request_keyframe()` calls before the pump loop; (c) config parser strips `"quotes"` from `config.cfg` values (`RTSP_FRAMERATE="30"` used to parse as 0 → gmlib rejected the encoder attr); (d) `sd_free_mb` uses `statfs` on `/tmp/sd` computed in 64-bit (a 32-bit `off_t` product overflows → reported negative MB → spurious "free space low" deletion); (e) audio-render init binds `GM_FILE_OBJECT`→`GM_AUDIO_RENDER_OBJECT` instead of a NULL source; (f) **CPU is high**: a fully-exclusive miio run holds ~50-100% system CPU (vs ~20% for rtspd) + `mmcqd`/`vp_slave` D-state and can trip the hardware watchdog after ~2-3 min (`sysMonit: cpu load 100/%`) — keep on-camera runs short and always stop rtspd/onvif/tracking first (double-run wedges the graph and reboots the camera). Not maintained as part of rtspd's ctrl machinery: do NOT assume `rtspd.c` ctrl/pending-args changes exist here.

## Active dev targets

- `tools/rtsp_server/rtspd.c` — the actively developed RTSP daemon. Build → `tools/bin/rtspd`. Links against `librtsp.a`, `librtsp_glibc.a`, `log/log.c`, and `libgm.so`. A `rtspd_ctrl_thread` (rtspd.c:2657) polls `/tmp/rtspd.ctrl` and **drains the whole file per poll** (multi-line bursts allowed, e.g. onvif `SetVideoEncoderConfiguration` writes `resolution`+`fps`+`gop`+`bitrate` at once; older code read only one line per poll and dropped the rest — that was the "ONVIF Set only staged resolution" bug). Accepted commands: `keyframe` (applied live) plus `restart`, `bitrate <kbps>`, `mode <1-4>`, `fps <num>`, `gop <num>`, `resolution WxH`, `bitrate_max <kbps>`, `h264profile <0|66|77|100>`, `h264level <0|31|40|41|50|51>`, `vui_cs <0|1>`, `vui_fr <0|1>`, `flip h|v|hv|0`, `rotation <0|90|180|270>`, `crop WxH+X+Y|0`, `watermark <hex|0>`. All except `keyframe` are staged into `/tmp/rtspd_pending_args` (`write_pending_arg`) and take effect via a ctrl-triggered self-restart (fork/handoff, `/tmp/rtspd_restart_oldpid`). `apply_pending_args()` (rtspd.c:2572) understands `bitrate=`/`mode=`/`fps=`/`gop=`/`width=`/`height=`/`bitrate_max=`/`h264profile=`/`h264level=`/`watermark=`/`vui_cs=`/`vui_fr=`/`hflip=`/`vflip=`/`rotation=`/`cropx=`/`cropy=`/`cropw=`/`croph=` keys; the args file is **not deleted** after apply, so consecutive changes (e.g. bitrate then mode) stack across restarts. `rtspd_reboot()` (rtspd.c:2453) waits 500ms before SIGTERM-ing itself so the child's `restart_handoff()` can still find the old PID in `/proc` (a non-restart start wipes pending args at rtspd.c:3439 — without the delay the args file is gone and the Set reverts). rtspd rewrites `/var/run/rtspd.pid` on every startup (it is NOT updated by the ctrl self-restart's `rtspd_reboot()` exec), so `S60rtsp stop` still targets the live instance after ctrl restarts instead of killing a stale pid and orphaning the real process. Still **command-line-only** (no ctrl counterpart): `-E` entropy/coding (cavlc|cabac), `-I` config preset (perf|light|quality|default), `-N` SAR, `-Z` ROI, `-Q` ROI QP, `-Y` fractional fps, `-K` QP bounds (applied in `gm_enc_init`, rtspd.c:1889-1891), `-T`/`-W` tamper, `-J` motion tracking (see below). `-c WxH+X+Y` crop and `-p WxH` prescale CLI options DO exist (rtspd.c:3716, 3734); crop is additionally ctrl-addressable, prescale is CLI-only. `-H <hex>` H264 watermark (rtspd.c:3703) is both CLI and ctrl-addressable. CLI-only flags reach a live camera via `RTSP_EXTRA_ARGS` in config.cfg → `S60rtsp` splices it into `DAEMON_OPTS` (S60rtsp:25) — the catch-all for `-E`, `-I`, `-K`, `-Y`, `-Q`, `-N`. Tamper/ROI/prescale now have **dedicated config keys** mapped by S60rtsp (S60rtsp:84-95): `TAMPER_ENABLED`+`TAMPER_THRESHOLD`+`TAMPER_SENSITIVE_B`/`TAMPER_SENSITIVE_H` → `-T 1 -W TH:B:H`, `ROI_ENABLED`+`ROI_RECT` (`x,y,w,h` in source pixels) → `-Z x,y,w,h`, `PRESCALE` (WxH|0 for off) → `-p WxH`. Tamper events fire `sdcard/firmware/scripts/tamper_on.sh`/`tamper_off.sh` (MQTT to `TAMPER_TOPIC`). `tools/rtsp_server/` also holds variants: `rtspd-chuangmi-v5.c` (built as `tools/bin/rtspd-v5` — shares VUI/ROI/flip/rotation/h264 options but has NO ctrl thread/pending-args machinery and NO tamper, so don't apply ctrl-interface changes there), `rtspd2MP.c` (built as `tools/bin/rtspd2MP` via `make build/rtspd2MP` — 1080p variant, full parity port of rtspd's ctrl/pending-args/tamper/tracking/flip/rotation/crop/prescale/VUI/SAR/ROI/QP/watermark/entropy/preset, plus rtspd2MP-only ctrl commands `osdmask` privacy mask, `osd_logo`, `checksum`, `fastforward` that rtspd.c does NOT handle — don't assume a ctrl change there also exists here), and older `rtspd-claude.c` and `osd.c` (committed binaries, no Makefile target).
- **Motion tracking / PTZ auto-follow**: `rtspd -J [deadzone:speed]` (defaults 2:3) makes the motion thread compute the centroid of active macroblocks (40x23 grid at 32x32px over 1280x720; `active_flag[i]==0` = motion) and write `center_col center_row mb_w mb_h count` to `/dev/shm/rtspd_tracking`, deleting the file on motion OFF. The **separate `tools/rtsp_server/tracking.c` daemon** (build → `tools/bin/tracking`, linked by `make build/tracking`) polls that file every 500ms, maps the centroid to motor coords (0..31 / 0..15), applies a deadzone, clamps to max speed (default 3 steps/move), and issues the same PWM+`/dev/motor` ioctls as `motor_ctrl.c` (software-tracked `cur_x/cur_y`, no hardware readback). It writes its own pid to `/var/run/tracking.pid` and `<state> <cur_x> <cur_y>` to `/dev/shm/rtspd_tracking_state` (both read by the web API), and runs `sdcard/firmware/scripts/tracking.sh on|off` on start/stop. Keeping it a separate process (rather than threading it into rtspd) protects the RTSP pipeline from motor-blocking sleeps. Options: `-d <deadzone>`, `-s <speed>`, `-z` return-home after 10s, `-v`. Gate: `MOTION_TRACKING=1` in config.cfg → S60rtsp adds `-d -J` and starts the tracking daemon with `TRACKING_SPEED` / `TRACKING_DEADZONE`. Web API: `GET /api/tracking/{status}`, `POST /api/tracking/{start,stop,blink,stop_blink}`. `tracking.sh` handles `on|off|status|blink|stop_blink`: blinks the blue LED (background loop, pid in `/var/run/tracking_led.pid`) + MQTT to `TRACKING_TOPIC`.
- `tools/utils/codec_ctrl.c` — CLI front-end to the rtspd ctrl file. Commands: `status [-j|-k]`, `keyframe`, `bitrate`, `mode`, `fps`, `gop`, `resolution WxH`, `bitrate_max`, `flip h|v|hv|0`, `rotation`, `crop WxH+X+Y|0`, `h264profile`, `h264level`, `vui_cs`, `vui_fr`, `watermark <hex|0>`, `zoom` (reads `/dev/shm/rtspd_zoom`). Each command writes the matching ctrl-file line; the web API wraps all of the setters (`/api/codec/<set>`) plus `status`/`keyframe`/`zoom`. `status -j` parses `/proc/videograph/gmlib_setting` into JSON.
- `tools/utils/take_snapshot.c` / `take_video.c` → `tools/bin/take_snapshot` / `tools/bin/take_video` (built by `all`, no dedicated `build/` target) — **blocking trigger helpers**: write `/dev/shm/rtspd_snapshot` (or `/dev/shm/rtspd_video`) and block until rtspd's `media_thread` unlinks it, then print the produced file's path. `take_snapshot` backs `timelapse.sh`; `take_video` backs `/api/record` (rtspd records ~`RECORDING_DURATION`=20s, auto-stops at 30 — same trigger as motion RECORD).
- `tools/onvif_server/onvif_server.c` — ONVIF server → `tools/bin/onvif_server`. `tools/rtsp_server/aac_play.c` → `tools/bin/aac_play` (`make build/aac_play`). Gated by `ENABLE_ONVIF=1` → `S65onvif` (nohup + `-P /var/run/onvif_server.pid` written by the daemon itself). SOAP endpoints on `:8899`, WS-Discovery multicast `:3702`; `GET /snapshot.jpg` triggers a real rtspd snapshot (same `/dev/shm/rtspd_snapshot` + `rtspd_web_snapshot_lock` coalescing as `/api/snapshot`) and streams back the JPEG. WAN access: `ONVIF_WAN_HOST`/`ONVIF_HTTP_PORT`/`ONVIF_RTSP_PORT` (config.cfg) → `--public-host/--public-http-port/--public-rtsp-port` → advertised in `GetCapabilities`/`GetStreamUri` (`rtsp://wan:port/live/ch00_0`) — the camera itself still binds 8899/554, only the advertised host/ports change. ONVIF advertises 1280x720@15, AAC 16k mono audio.
  - **Auth (fail-open)**: enabled only when BOTH `ONVIF_USER` and `ONVIF_PASS` are set in config.cfg (S65onvif passes them as `--user=`/`--pass=`, overriding CLI). Empty = open access (backward compatible). Enforced in `client_thread` on POST /onvif/ → HTTP 401 + SOAP fault. Accepts WS-UsernameToken `PasswordText` (plain) OR `PasswordDigest` = Base64(SHA1(rawNonce + wsu:Created + password)) — hash computed in-process (own SHA-1/Base64 in onvif_server.c, no openssl dep). `xml_tag()` (onvif_server.c:484) does **prefix-aware open-tag matching** with a delimiter check after the name (`>`, space, tab, newline, or `/`) so `<wsse:Username` does NOT match `<wsse:UsernameToken>` (that prefix collision made all correct-credential accept paths return 401 while reject paths — which don't inspect values — still "worked"; the auth-fail bug). Verified on-camera: PasswordText+`PasswordDigest` correct → 200, missing/wrong creds → 401.
  - SOAP surface (beyond base set): `GetVideoEncoderConfigurations/Options/Configuration` + `SetVideoEncoderConfiguration` (live values read from `/proc/videograph/gmlib_setting` via `enc_get`, ~same as `codec_ctrl`; Set writes `resolution WxH`/`fps N`/`gop N`/`bitrate kbps`/`h264profile 66|77|100` to `/tmp/rtspd.ctrl`, clamped to 160..1280 x 120..720, fps≤30, gop≤60, bitrate≥32kbps — takes effect on rtspd self-restart), `GetVideoSourceConfigurations/Options/Configuration`, `GetScopes`, `SetSystemDateAndTime` (`settimeofday`, UTCDateTime or LocalDateTime+TZ offset, TZ parsed from `UTC±HH:MM`/`±HH:MM`), `GetSystemDateAndTime` (real UTC via `gmtime_r`), `Get/SetHostname` (`/proc/sys/kernel/hostname`), `GetNetworkInterfaces` (mlan0→wlan0, MAC from sysfs, prefix from `SIOCGIFNETMASK`), `GetNetworkProtocols`, `GetUsers` (echoes ONVIF_USER when auth on), `SystemReboot` (detached thread, `reboot(RB_AUTOBOOT)`→`/sbin/reboot` fallback, response sent first), `SetHomePosition/GotoHomePosition/GetHomePosition` (ptz struct `home_x/home_y/home_zoom`), `RemovePreset`, `GetServiceCapabilities` (dispatch by `tptz`/`trt`/device prefix in body).
  - Branch-order C gotcha: substring matching requires plural before Options before singular (e.g. `GetVideoEncoderConfigurations` → `...ConfigurationOptions` → `GetVideoEncoderConfiguration`), and `GetCapabilities` is guarded with `&&!strstr(r,"GetServiceCapabilities")` since that string contains `GetCapabilities`.
  - Build: `make build/onvif_server`; CI `build-onvif.yml` is **manual-trigger only** (no auto build on push — trigger `gh workflow run build-onvif.yml` after editing; the workflow commits the rebuilt `tools/bin/onvif_server` itself).
- `tools/rtsp_server/rtsp_audio_in.c` → `tools/bin/rtsp_audio_in` — **downlink / two-way audio** receiver (client → camera speaker). The RTSP network layer used by rtspd (`librtsp.a`) is a prebuilt static lib with NO inbound audio callback, so the downlink receiver is a **separate process** (not inside rtspd). It reuses the exact `aac_play.c` render binding (`GM_FILE_OBJECT`→`GM_AUDIO_RENDER_OBJECT`, same attr offsets/ABI 52) and feeds `gm_send_multi_bitstreams`. Usage: `rtsp_audio_in [-p recvport=5004] [-c {aac|ulaw|alaw|pcm}] [-r rate=16000] [-g ch=1] [-v]`. AAC path reads RFC 3640 MPEG4-GENERIC AUs (rtspd AUSize convention) OR raw ADTS and rebuilds ADTS-LC mono @ cfg rate; G.711 → PCM / raw PCM switch the render `encode_type` between GM_AAC=2 and GM_PCM=1 (PCM/8k/32k acceptance on the ADDA308 is UNPROVEN — vendor path is AAC-LC 16 kHz mono; test on-camera). Build: `make build/rtsp_audio_in` (wired into `all` and CI `build-rtspd.yml`, force-added binary). Two-way audio needs BOTH the existing rtspd uplink (mic→client ) AND this downlink process running alongside.
- On-camera two-way test: `rtsp_audio_in -p 5004 -c aac -r 16000` on the camera, then push RTP to `<camera>:5004` (e.g. `ffmpeg -re -i in.aac -c:a aac -ar 16000 -ac 1 -f rtp 'rtp://<camera>:5004'`, or a G.711 sender for `-c ulaw/alaw`).
- `tools/lib/*.c` — shared `libchuangmi_*.so` libs (ircut, led, pwm, isp328, utils); `tools/utils/*.c` — one-off camera utilities. Both build against GM libs in `tools/gm_lib/` (headers in `inc/`, shared libs in `lib/`).
- The removed `tools/gm8136-rtsp-audio/` subtree is gone (deleted Sep 2026); don't re-add or reference it.

## Web UI / profiles

- The web frontend **is now part of this repo** under `sdcard/firmware/www/public/` (was removed in 2019, previously a separate repo `miicamweb` downloaded as `website.tgz` via the now-commented-out `tools/dev/download-website.sh`). It's a pure-PHP backend + vanilla JS SPA:
  - `public/api/index.php` — router (no framework/vendor). All `/api/*` requests are rewritten here by lighttpd. The router parses the resource path out of `REQUEST_URI` (lighttpd preserves the original URI through the internal rewrite). **Must stay PHP-7.2-compatible** (the camera runs `arm-php-cgi` 7.2.12): no arrow functions `fn()`, no `??=`, no trailing commas in calls, no `match`/`str_contains`, no typed properties. Lint the uclibc/7.2 subset with a modern `php -l` is NOT sufficient — features like `fn()` parse-OK on 8.x but fatal on 7.2.
  - Endpoints: `GET /api/status` (camera modes, LEDs, codec status via `codec_ctrl status -j`, motion, last media), `GET /api/snapshot` (touch `/dev/shm/rtspd_snapshot` → rtspd captures JPEG, returned directly as `image/jpeg`), `GET/POST /api/codec/{status,zoom}` + `GET/POST /api/codec/<set>` for `bitrate|fps|gop|mode|resolution|bitrate_max|flip|rotation|crop|h264profile|h264level|vui_cs|vui_fr|watermark` (all accept `value`, map to `codec_ctrl <set> <value>`, ctrl-side and staged-on-restart), `POST /api/keyframe`, `GET /api/motor/status` + `POST /api/motor/{left,right,up,down,home,goto,stop}` (`stop` falls back to `home`) + `POST /api/motor/preset/{save,list,clear,goto}` (slot 0-15, save also takes a `name`), `GET/POST /api/camera/{info|<type>}` (`camera_adjust -j` emits keys with **trailing spaces** — callers must trim; adjust keys: brightness/contrast/hue/saturation/denoise/sharpness/gamma_type/dr_mode; `POST /api/camera/reset` runs `camera_adjust -r`), `POST /api/mode/<name>/<on|off>` (nightmode, ir_cut, ir_led, blue_led, yellow_led, mirrormode, flipmode), `GET/POST /api/config` (reads/writes `/tmp/sd/config.cfg`; validates each `KEY=value`/comment line and normalizes by trimming; backs up to `.bak` first; **`POST` accepts `patch=1` + `keys[K]=v` to merge single keys into the existing file instead of replacing it wholesale** — required by the Settings page) + `GET /api/config/export` (download as `<hostname>-config.cfg`), `POST /api/config/restore` (puts `.bak` back, keeping `.prev`), `POST /api/config/import` (multipart `file` upload or `raw` text), `GET /api/services` + `POST /api/service/<name>/<start|stop|restart|status>` (init scripts in `sdcard/firmware/etc/init` with `S##` prefixes — e.g. S60rtsp, S65onvif; the API resolves bare names like `rtsp`/`onvif` to their script; `/api/services` also reports `ntpd`, `logging`, `mqtt-control`, `mqtt-interval`, `restartd`, `auto_night_mode`, `restore_state`, `timelapse`), `GET /api/system`, `GET /api/sdcard`, `GET /api/last/<image|video>`, `POST /api/record` (runs `take_video` → it touches `/dev/shm/rtspd_video`, the same segment trigger rtspd handles for motion RECORD; blocks until a segment is written, returns its path/URL). Note `/api/tracking/status|blink|stop_blink` work through `tracking.sh` WITHOUT the `tracking` binary present (only `/api/tracking/start` requires it to spawn the daemon); `start` also runs `tracking.sh on` and `stop` runs `tracking.sh off` so LED blink + MQTT announce stay in sync.
  - **No streaming endpoint**: lighttpd's `mod_cgi` buffers the whole CGI output until process exit, so multipart `x-mixed-replace` cannot work through `arm-php-cgi`. There is no `/api/stream`; the SPA's live view polls `GET /api/snapshot` every ~3s (`startStream`/`stopStream` in app.js). rtspd's snapshot take ~2s each, so 3s is the minimum sane poll cadence.
  - **Snapshot overload guard**: rtspd's `take_snapshot()` runs **synchronously inside `media_thread`** (~2s), so queued triggers starve RTSP and trip the hardware watchdog → camera reboot (a freshly-booted rtspd at a new PID — the "Start stream adds an rtspd PID" bug). `ep_snapshot` coalesces via a shared `/dev/shm/rtspd_web_snapshot_lock` stamp (`SNAP_LOCK`/`SNAP_MIN_INTERVAL`=3): only one caller per 3s actually touches the trigger; the rest return the newest JPEG on disk. Verified: 5 concurrent `/api/snapshot` → 1 fresh JPEG, rtspd PID unchanged.
  - Snapshot/stream trigger contract: rtspd polls for existence of `/dev/shm/rtspd_snapshot` and **unlinks it** per request (rtspd.c:1548), then `take_snapshot()` (rtspd.c:826) writes `/tmp/sd/RECORDED_IMAGES/%Y/%m/%d/snapshot_%H%M%S.jpg` (quality 80, 1280x720, 500ms timeout) and records the absolute path to `/dev/shm/rtspd_last_snapshot_path`. `S60rtsp` pre-seeds the last-* path files with `get_last_image`/`get_last_video` from `functions.sh`.
  - `public/static/js/app.js` + `index.html` — tabbed SPA (Home=live view + snapshot + **on-screen PTZ d-pad** + motion/tracking status; Settings=**video customization** in groups: Format `RTSP_WIDTH/HEIGHT/BITRATE/BITRATE_MODE/FRAMERATE` + live flip, with "Apply resolution & codec now" hitting `/api/codec/{resolution,bitrate,fps,mode}`; Security `RTSP_USER/RTSP_PASS` only — web-auth UI was removed (mod_auth broken); Day/Night live toggles + `AUTO_NIGHT_MODE`; Motion `MOTION_DETECTION/MOTION_TAKE_SNAPSHOT/MOTION_RECORD/MOTION_TRACKING` + `TRACKING_SPEED/DEADZONE`; Audio `RTSP_AUDIO_TYPE/RATE` (volume is config-only, no driver backend); OSD `RTSP_OSD_TEXT/COLOR/SIZE` (timestamp is always-on in rtspd); Network `WIFI_SSID/PASS`; MQTT `ENABLE_MQTT/HOST/PORT/USER/PASS/TOPIC/STATUSINTERVAL`; System `CAMERA_HOSTNAME`/`TIMEZONE`/`NTP_SERVER` (via S30ntpd); Services autostart `ENABLE_*` toggles (applied next boot); Advanced tamper `TAMPER_ENABLED/TAMPER_THRESHOLD/TAMPER_SENSITIVE_B/H` + ROI `ROI_ENABLED/ROI_RECT` + `PRESCALE`; Timelapse `ENABLE_TIMELAPSE/TIMELAPSE_INTERVAL/TIMELAPSE_DURATION` + "Record now" (`POST /api/record`) + "Restart RTSP" — saves via `patch=1` to `/api/config`; per-group Save + "Apply now"), Config=legacy device settings (modes/LEDs/camera_adjust/encoder/motor + **PTZ preset panel** + **config export/import/restore** + camera reset) + config.cfg textarea, Info=**dashboard** (Camera status / System status / Network status tables), SDCard=df + last media). Live view polls `/api/snapshot?<ts>` every ~3s. POSTs use form-encoding (php.ini `max_input_vars=20` — don't send big key arrays; each Settings group sends only its own keys, staying safely under the limit even with the 7-key MQTT/Motion groups).
  - `GET /api/system` returns host/kernel/uptime/ip/loadavg/meminfo **and** a `network` object (ip, mac, gateway from `route -n`, wifi essid/bitrate/link_quality/signal_dbm/ap from `iwconfig`) feeding the Info dashboard.
- Infrastructure the UI shells out to: `sdcard/firmware/etc/lighttpd.conf` (serves `.../www/public`, **no basic auth** — `mod_auth` is broken on this lighttpd 1.4.48 build, all hash formats 401 even with correct creds; an empty `/etc/lighttpd.user` 401s everything, so auth was dropped entirely, aliases `/snapshots/`→`RECORDED_IMAGES`, `/videos/`→`RECORDED_VIDEOS`) + `S50lighttpd`. PHP-CGI (`arm-php-cgi`) execs `BIN/{codec_ctrl,motor_ctrl,camera_adjust,nightmode,ir_cut,ir_led,blue_led,yellow_led,mirrormode,flipmode}` (all in `/tmp/sd/firmware/bin`). Boot gating lives in `scripts/.boot.sh`: lighttpd only starts if `ENABLE_HTTPD=1` in config.cfg (default in `configupdate`); the SD copy of `lighttpd.conf` is what gets placed into tmpfs `/etc/` at boot. `.boot.sh` self-heals a clobbered `firmware/bin` (restores missing bins from a bundled tarball in `sdcard/`), cleans stray FT payload files out of it, and later `mount --rbind`s `firmware/bin` at `/tmp/sd/ft`.
  - **CRLF hazard**: the camera's busybox `sh` hard-fails on CRLF init scripts (`\r: not found`). `.gitattributes` forces `text eol=lf` on `sdcard/firmware/etc/init/*`, `etc/lighttpd.conf`, `scripts/**`, `sdcard/ft/*.sh`, `sdcard/ft/*.pem` and `config.cfg` — the CRLF→LF normalization of the legacy `sdcard/firmware/etc/*` + `scripts/*` files is now **committed** (HEAD stores LF), so don't re-introduce `\r` or add CRLF-stripping commit churn for files already covered by the globs. The hazard only really remains for **new** files not covered by a `.gitattributes` pattern (add the file to `.gitattributes` when creating it) and for files deployed by hand. Note the `sdcard/firmware/scripts/.boot.sh` placement of `lighttpd.conf` into tmpfs `/etc/` happens at boot from the committed (LF) copy.
- Timelapse: `sdcard/firmware/scripts/timelapse.sh {start|stop|restart|status}` drives periodic snapshot capture — it shells out to the `take_snapshot` binary (the blocking rtspd snapshot trigger) and copies each fresh JPEG into `/tmp/sd/timelapse/YYYY-MM-DD/`, pid in `/var/run/timelapse.pid`. `S76timelapse` auto-starts it at boot only when `ENABLE_TIMELAPSE=1`; keys `TIMELAPSE_INTERVAL` (seconds, default 10 — keep ≥3, one snapshot costs rtspd ~2s) and `TIMELAPSE_DURATION` (minutes, 0=run until stopped). Exposed via the web Settings→Timelapse group and `/api/service/timelapse/*`.
- Build: the `website` Makefile target requires `sdcard/firmware/www/public/{index.html,api/index.php}`. The whole `sdcard/firmware/www/` tree is **committed** (re-added after the 2019 removal), so `make all`/`images` works from a fresh clone. `make clean` does not wipe `sdcard/firmware/www` (not a downloaded tarball anymore).
- Note the sensor is 720p-native (`MAX_FPS 30`, gmlib `capture_max_fps=30`, `rtspd.c` clamps fps > MAX_FPS and height > 720; live capture max still read from `gm_system.cap[0].framerate` in `gm_graph_init` so a 15-fps gmlib.cfg caps you there too); only downscale resolutions are available — upscaling above native may fail `gm_bind()`. Max encoder bitrate is 10240K (`gmlib.cfg` `max_bitrate = 8M/10240K, ...`), which rtspd/codec_ctrl/onvif cap at.

## Motor control

- `tools/utils/motor_ctrl.c` — CLI tool for PTZ motor control (renamed from `motor_control`). Build → `tools/bin/motor_ctrl`. Commands: `left`, `right`, `up`, `down`, `home`, `goto <x> <y>`, `pos`, `status`, `stop`, `zoom`, `preset save|goto|list|clear`, `calibrate`, `sync`.
- `tools/onvif_server/onvif_server.c` has inline motor control (does NOT use `motor_driver.c`).
- `tools/onvif_server/motor_driver.c` + `motor_driver.h` — standalone motor library compiled into onvif_server but **never called** (dead code). `onvif_server.c` has its own inline motor ioctl code.
- **Hardware quirk**: `H_COORD_GET`/`V_COORD_GET` ioctls always return 0 on this SoC. Both `motor_ctrl.c` and `onvif_server.c` track position via software deltas (`cur_x += dx`) instead of reading hardware. The `sync` command in motor_ctrl can re-read from hardware if needed.
- Direction mapping (same in all three files): horizontal `dx>0→dir=0` (right), `dx<0→dir=1` (left); vertical `dy>0→dir=1` (up), `dy<0→dir=0` (down).

## Building locally (what CI does — fastest path for a single binary)

1. Extract `sdk/toolchain_gnueabi-4.4.0_ARMv5TE.tgz` and `sdk/gm_lib_2015-01-09-IPCAM.tgz`, then `chmod -R +x` the SDK.
2. The 32-bit gcc 4.4.0 host binaries need 32-bit libs on a modern 64-bit host: `sudo apt-get install libc6:i386 libstdc++6:i386 lib32z1 libmpfr6:i386 libgmp10:i386`, plus symlinks:
   ```
   sudo ln -sf /usr/lib/i386-linux-gnu/libmpfr.so.6 /usr/lib/i386-linux-gnu/libmpfr.so.4
   sudo ln -sf /usr/lib/i386-linux-gnu/libgmp.so.10 /usr/lib/i386-linux-gnu/libgmp.so.3
   ```
3. `export PATH=<toolchain>/usr/bin:$PATH`, then `make build/<target>`.

WSL quirk: the 32-bit toolchain cannot read sources on Windows drvfs (`/mnt/c`) and fails with "Value too large for defined data type". The busybox build already works around this by staging in `$(HOME)/.miicam-build` (override with `MIICAM_NATIVEDIR`); expect the same error for other packages if you build the full image directly in WSL instead of in the container.

## Git / CI quirks

- `tools/bin/*`, `tools/lib/*.so`, and `sdcard/firmware/bin/*` are gitignored, yet some binaries are committed. CI force-adds them (`git add -f tools/bin/rtspd`, etc.). If you edit C code and rebuild, commit the binary with `git add -f tools/bin/<name>`, not plain `git add`.
- The working tree holds lots of **untracked local scratch** that is NOT part of the firmware and must not be committed or documented: `sdcard-Mijia-1080p/` (experimental 1080p fork tree), `chuangmi-v5-dump/` (firmware dump from another camera, extracted for comparison), and `camera_dump/` (newer camera dump tarballs). `opencode.json` does not exist in the repo.
- `codespace` is the active working branch (this checkout is on `codespace`; `master` is not checked out locally). It holds all CI workflows, vs `master` which has fewer. Workflows present on `codespace`: `build-rtspd.yml` (auto-triggers on push to `tools/rtsp_server/**`/`Makefile` AND `workflow_dispatch`, builds `rtspd`/`rtspd-v5`/`rtsp_audio_in`/`tracking`/`rtspd2MP`, force-adds `rtspd`/`rtspd-v5`/`rtsp_audio_in`/`tracking` (required), plus optional `rtspd2MP`/`rtspd2MP00` (tolerated if absent — `rtspd2MP00` no longer exists)), `build-libs.yml` (auto-triggers on push for `tools/lib/**`, `tools/utils/**`, `Makefile`, force-adds `tools/lib/*.so` + `tools/bin/*`), `build-onvif.yml`, `build-aac-play.yml`.
- `build-aac-play.yml` compiles `aac_play.c` directly with `$(TOOLCHAIN_PREFIX)-gcc` (independent of the `make build/aac_play` target, which now builds aac_play correctly after the `aac_player.c` filename bug in the Makefile was fixed).

## Deploying to a camera

- Camera mounts the SD at `/tmp/sd`; binaries live at `/tmp/sd/firmware/bin`. `tools/dev/helpers.sh` (sourced inside the build container) provides `rb <target>` and `upload_rtsp`/`upload_binary`/`upload_libs` via `scp root@$CAMERA_HOSTNAME`; requires `tools/dev/host.cfg` (gitignored, template at `host.cfg.example`) with the camera hostname.
- `sdcard/config.cfg` is the camera config and is generated (not hand-edited) by `sdcard/firmware/scripts/update/configupdate`; the target device reads `/tmp/sd/config.cfg`.
- **SSH/dropbear**: the camera runs dropbear 2026.94 (newer than the old 2018.76 the SDK shipped). `tools/make/dropbear.mk` builds dropbear 2026.94 + sftp-server 10.5p1 (OpenSSH) — the old dropbear cannot reach a newer sftp-server (`/usr/libexec/sftp-server: not found`). Built `/tmp/sd/firmware/bin/sftp-server` is a real binary, not a symlink (vfat). `S20dropbear` gates on `ENABLE_SSHD=1` in config.cfg; its start uses `nohup dropbear -R -p 22 -P ${PIDFILE}` — the `$PIDFILE` var MUST be defined *before* `$DAEMON_OPTS` (shell expands it at assignment), and relying on `${PIDFILE}` so stop always kills the real listener (busybox `start-stop-daemon --make-pidfile` records a wrong pid on this system). Host keys: `/etc/dropbear/` is tmpfs; `recover_key`/`save_key` persist `dropbear_*_host_key` to `/tmp/sd/firmware/etc/dropbear/` so the host key doesn't change every boot. Committed dropbear 2026.94/10.5p1 binaries live under `sdcard/dropbear/` (added while `sdcard/firmware/bin` is not part of the tree).
