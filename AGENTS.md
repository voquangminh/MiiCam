# AGENTS.md

Alternate firmware for the Xiaomi Chuangmi 720p IP camera (Grain Media GM8136S SoC). Everything cross-compiles to `arm-unknown-linux-uclibcgnueabi` (ARMv5TE, uclibc, gcc 4.4.0) and is bundled onto an SD card (`sdcard/`) flashed into the camera. There is no test suite; verification = cross-compile + run on a real camera.

## Build system

- Canonical full build is Docker-based: `./manage.sh --shell` (interactive build env), `--build` (runs `make images clean`), `--build-docker`, `--all`. Toolchain is expected at `/usr/src/arm-linux-3.3/toolchain_gnueabi-4.4.0_ARMv5TE/usr/bin` inside the container.
- Top-level `Makefile` builds everything (`all`), packs the SD image (`images` → `MiiCam.zip`/`MiiCam.tgz`), and `clean` wipes `src/`, `prefix/`, `build/`, `tools/bin`, `tools/lib/*.so`, **and `sdcard/firmware/bin` + `sdcard/firmware/lib`** (committed binaries get deleted too — repopulate with `make install`). Note `all` builds `rtspd`, `rtspd-v5`, `rtsp_audio_in`, `onvif_server` but NOT `aac_play`.
- Third-party source tarballs are downloaded into `src/` (gitignored) per `tools/dev/sources.json` by `tools/dev/download-sources.py`; each `tools/make/*.mk` downloads/extracts/builds one package into `prefix/`.
- To build only a specific target: `make build/<target>` (e.g. `build/rtspd`, `build/onvif_server`).

## Active dev targets

- `tools/rtsp_server/rtspd.c` — the actively developed RTSP daemon. Build → `tools/bin/rtspd`. Links against `librtsp.a`, `librtsp_glibc.a`, `log/log.c`, and `libgm.so`. A `rtspd_ctrl_thread` polls `/tmp/rtspd.ctrl`; accepted commands are exactly `keyframe` (immediate), `bitrate <kbps>`, `mode <1-4>`, `fps <num>`, `gop <num>`. The latter four are staged into `/tmp/rtspd_pending_args` (`write_pending_arg`) and take effect via a ctrl-triggered self-restart (fork/handoff, `/tmp/rtspd_restart_oldpid`); `apply_pending_args()` only understands `bitrate=`/`mode=`/`fps=`/`gop=` keys. All other knobs are **command-line-only**, not ctrl-addressable: `-F` flip, `-G` rotation, `-V` h264 profile, `-L` level, `-E` entropy, `-I` config preset, `-U` VUI full-range, `-N` SAR, `-Z`/`-Q` ROI, `-Y` fractional fps, `-K` QP bounds, `-T`/`-W` tamper. There is **no** `-c` crop or `-p` prescale option (older AGENTS.md claims are stale). `tools/rtsp_server/` also holds variants: `rtspd-chuangmi-v5.c` (built as `tools/bin/rtspd-v5` — shares VUI/ROI/flip/rotation/h264 options but has NO ctrl thread/pending-args machinery and NO tamper, so don't apply ctrl-interface changes there), plus older `rtspd-claude.c`, `rtspd2MP.c`, `osd.c` (committed binaries but not the active feature target, no Makefile target).
- `tools/utils/codec_ctrl.c` — CLI front-end to the rtspd ctrl file. Commands: `status [-j|-k]`, `keyframe`, `bitrate`, `mode`, `fps`, `gop`, `zoom` (reads a zoom-state file). Nothing else; `resolution`/`flip`/`rotation`/`h264profile`/`vui_*` were in an older version and are gone. `status -j` parses `/proc/videograph/gmlib_setting` into JSON.
- `tools/onvif_server/*.c` — ONVIF server → `tools/bin/onvif_server`. `tools/rtsp_server/aac_play.c` → `tools/bin/aac_play`. Note: the Makefile references `aac_player.c` but the actual file is `aac_play.c`; this will cause a build failure for `make build/aac_play` until fixed.
- `tools/rtsp_server/rtsp_audio_in.c` → `tools/bin/rtsp_audio_in` — **downlink / two-way audio** receiver (client → camera speaker). The RTSP network layer used by rtspd (`librtsp.a`) is a prebuilt static lib with NO inbound audio callback, so the downlink receiver is a **separate process** (not inside rtspd). It reuses the exact `aac_play.c` render binding (`GM_FILE_OBJECT`→`GM_AUDIO_RENDER_OBJECT`, same attr offsets/ABI 52) and feeds `gm_send_multi_bitstreams`. Usage: `rtsp_audio_in [-p recvport=5004] [-c {aac|ulaw|alaw|pcm}] [-r rate=16000] [-g ch=1] [-v]`. AAC path reads RFC 3640 MPEG4-GENERIC AUs (rtspd AUSize convention) OR raw ADTS and rebuilds ADTS-LC mono @ cfg rate; G.711 → PCM / raw PCM switch the render `encode_type` between GM_AAC=2 and GM_PCM=1 (PCM/8k/32k acceptance on the ADDA308 is UNPROVEN — vendor path is AAC-LC 16 kHz mono; test on-camera). Build: `make build/rtsp_audio_in` (wired into `all` and CI `build-rtspd.yml`, force-added binary). Two-way audio needs BOTH the existing rtspd uplink (mic→client ) AND this downlink process running alongside.
- On-camera two-way test: `rtsp_audio_in -p 5004 -c aac -r 16000` on the camera, then push RTP to `<camera>:5004` (e.g. `ffmpeg -re -i in.aac -c:a aac -ar 16000 -ac 1 -f rtp 'rtp://<camera>:5004'`, or a G.711 sender for `-c ulaw/alaw`).
- `tools/lib/*.c` — shared `libchuangmi_*.so` libs (ircut, led, pwm, isp328, utils); `tools/utils/*.c` — one-off camera utilities. Both build against GM libs in `tools/gm_lib/` (headers in `inc/`, shared libs in `lib/`).
- `tools/gm8136-rtsp-audio/` is a standalone parallel subtree (own `Dockerfile`/`Makefile`/`build.sh`, vendored SDK under its `sdk/`). It is NOT wired into the top-level Makefile and its `gm_lib/` is untracked locally. Don't assume edits there affect `tools/bin/rtspd`.

## Web UI / profiles

- The web frontend **is now part of this repo** under `sdcard/firmware/www/public/` (was removed in 2019, previously a separate repo `miicamweb` downloaded as `website.tgz` via the now-commented-out `tools/dev/download-website.sh`). It's a pure-PHP backend + vanilla JS SPA:
  - `public/api/index.php` — router (no framework/vendor). All `/api/*` requests are rewritten here by lighttpd. The router parses the resource path out of `REQUEST_URI` (lighttpd preserves the original URI through the internal rewrite). **Must stay PHP-7.2-compatible** (the camera runs `arm-php-cgi` 7.2.12): no arrow functions `fn()`, no `??=`, no trailing commas in calls, no `match`/`str_contains`, no typed properties. Lint the uclibc/7.2 subset with a modern `php -l` is NOT sufficient — features like `fn()` parse-OK on 8.x but fatal on 7.2.
  - Endpoints: `GET /api/status` (camera modes, LEDs, codec status via `codec_ctrl status -j`, motion, last media), `GET /api/snapshot` (touch `/dev/shm/rtspd_snapshot` → rtspd captures JPEG, returned directly as `image/jpeg`), `GET/POST /api/codec/{status,bitrate,fps,gop,mode}`, `POST /api/keyframe`, `GET /api/motor/status` + `POST /api/motor/{left,right,up,down,home,goto,stop}` (`stop` falls back to `home`), `GET/POST /api/camera/{info|<type>}` (`camera_adjust -j` emits keys with **trailing spaces** — callers must trim; adjust keys: brightness/contrast/hue/saturation/denoise/sharpness/gamma_type/dr_mode), `POST /api/mode/<name>/<on|off>` (nightmode, ir_cut, ir_led, blue_led, yellow_led, mirrormode, flipmode), `GET/POST /api/config` (reads/writes `/tmp/sd/config.cfg`; validates each `KEY=value`/comment line and normalizes by trimming; backs up to `.bak` first; **`POST` accepts `patch=1` + `keys[K]=v` to merge single keys into the existing file instead of replacing it wholesale** — required by the Settings page), `GET /api/services` + `POST /api/service/<name>/<start|stop|restart|status>` (scripts `S99*` in `sdcard/firmware/etc/init`), `GET /api/system`, `GET /api/sdcard`, `GET /api/last/<image|video>`.
  - **No streaming endpoint**: lighttpd's `mod_cgi` buffers the whole CGI output until process exit, so multipart `x-mixed-replace` cannot work through `arm-php-cgi`. There is no `/api/stream`; the SPA's live view polls `GET /api/snapshot` every ~3s (`startStream`/`stopStream` in app.js). rtspd's snapshot take ~2s each, so 3s is the minimum sane poll cadence.
  - **Snapshot overload guard**: rtspd's `take_snapshot()` runs **synchronously inside `media_thread`** (~2s), so queued triggers starve RTSP and trip the hardware watchdog → camera reboot (a freshly-booted rtspd at a new PID — the "Start stream adds an rtspd PID" bug). `ep_snapshot` coalesces via a shared `/dev/shm/rtspd_web_snapshot_lock` stamp (`SNAP_LOCK`/`SNAP_MIN_INTERVAL`=3): only one caller per 3s actually touches the trigger; the rest return the newest JPEG on disk. Verified: 5 concurrent `/api/snapshot` → 1 fresh JPEG, rtspd PID unchanged.
  - Snapshot/stream trigger contract: rtspd polls for existence of `/dev/shm/rtspd_snapshot` and **unlinks it** per request, then `take_snapshot()` (`rtspd.c:1522-1534`, `809`) writes `/tmp/sd/RECORDED_IMAGES/%Y/%m/%d/snapshot_%H%M%S.jpg` (quality 80, 1280x720, 500ms timeout) and records the absolute path to `/dev/shm/rtspd_last_snapshot_path`. `S99rtsp` pre-seeds the last-* path files with `get_last_image`/`get_last_video` from `functions.sh`.
  - `public/static/js/app.js` + `index.html` — tabbed SPA (Home=live view + snapshot, Settings=**video customization** in 6 groups: Format `RTSP_WIDTH/HEIGHT/BITRATE/BITRATE_MODE/FRAMERATE` + live flip; Security `RTSP_USER/RTSP_PASS` + web API user/pass; Day/Night live toggles + `AUTO_NIGHT_MODE`; Audio `RTSP_AUDIO_TYPE/RATE` (volume is config-only, no driver backend); OSD `RTSP_OSD_TEXT/COLOR/SIZE` (timestamp is always-on in rtspd); Network `WIFI_SSID/PASS` — saves via `PATCH /api/config`; per-group Save + "Apply now"), Config=legacy device settings (modes/LEDs/camera_adjust/encoder/motor/services) + config.cfg textarea, Info=**dashboard** (Camera status / System status / Network status tables), SDCard=df + last media). Live view polls `/api/snapshot?<ts>` every ~3s. POSTs use form-encoding (php.ini `max_input_vars=20` — don't send big key arrays; each Settings group sends only its own keys).
  - `GET /api/system` returns host/kernel/uptime/ip/loadavg/meminfo **and** a `network` object (ip, mac, gateway from `route -n`, wifi essid/bitrate/link_quality/signal_dbm/ap from `iwconfig`) feeding the Info dashboard.
- Infrastructure the UI shells out to: `sdcard/firmware/etc/lighttpd.conf` (serves `.../www/public`, **no basic auth** — `mod_auth` is broken on this lighttpd 1.4.48 build, all hash formats 401 even with correct creds; an empty `/etc/lighttpd.user` 401s everything, so auth was dropped entirely, aliases `/snapshots/`→`RECORDED_IMAGES`, `/videos/`→`RECORDED_VIDEOS`) + `S99lighttpd`. PHP-CGI (`arm-php-cgi`) execs `BIN/{codec_ctrl,motor_ctrl,camera_adjust,nightmode,ir_cut,ir_led,blue_led,yellow_led,mirrormode,flipmode}` (all in `/tmp/sd/firmware/bin`). Boot gating lives in `scripts/.boot.sh`: lighttpd only starts if `ENABLE_HTTPD=1` in config.cfg (default in `configupdate`); the SD copy of `lighttpd.conf` is what gets placed into tmpfs `/etc/` at boot.
  - **CRLF hazard**: repo files under `sdcard/firmware/etc/init/*` and `lighttpd.conf` may be CRLF (Windows checkout). The camera's busybox `sh` will hard-fail on CRLF init scripts (`\r: not found`), and lighttpd tolerates it but prefer LF. When deploying/editing shell scripts, strip `\r` (the S99rtsp audio/OSD compose edits in this repo are LF-normalized).
- Build: the `website` Makefile target requires `sdcard/firmware/www/public/{index.html,api/index.php}`. NOTE: in this checkout the whole `sdcard/firmware/www/` tree is **untracked** (in-progress re-addition after the 2019 removal); a fresh clone lacks it, so `make all`/`images` will fail until it is committed. `make clean` does not wipe `sdcard/firmware/www` (not a downloaded tarball anymore).
- Note the sensor is 720p-native (MAX_FPS 15, `rtspd.c` clamps/errors on fps > 15 and height > 720); only downscale resolutions are available — upscaling above native may fail `gm_bind()`.

## Motor control

- `tools/utils/motor_ctrl.c` — CLI tool for PTZ motor control (renamed from `motor_control`). Build → `tools/bin/motor_ctrl`. Commands: `left`, `right`, `up`, `down`, `home`, `goto <x> <y>`, `pos`, `status`, `stop`, `zoom`, `preset save|goto|list|clear`, `calibrate`, `sync`.
- `tools/onvif_server/onvif_server.c` has inline motor control (does NOT use `motor_driver.c`).
- `tools/onvif_server/motor_driver.c` + `motor_driver.h` — standalone motor library compiled into onvif_server but **never called** (dead code). `onvif_server.c` has its own inline motor ioctl code.
- **Hardware quirk**: `H_COORD_GET`/`V_COORD_GET` ioctls always return 0 on this SoC. Both `motor_ctrl.c` and `onvif_server.c` track position via software deltas (`cur_x += dx`) instead of reading hardware. The `sync` command in motor_ctrl can re-read from hardware if needed.
- Direction mapping (same in all three files): horizontal `dx>0→dir=0` (right), `dx<0→dir=1` (left); vertical `dy>0→dir=1` (up), `dy<0→dir=0` (down).

## Building locally (what CI does — fastest path for a single binary)

1. Extract `sdk/toolchain_gnueabi-4.4.0_ARMv5TE.tgz` and `sdk/gm_lib_2015-01-09-IPCAM.tgz`, then `chmod -R +x` the SDK.
2. The 32-bit gcc 4.4.0 host binaries need 32-bit libs on a modern 64-bit host: `sudo apt-get install libc6:i386 libstdc++6:i386 lib32z1 libmpfr6:i386 libgmp10:i386`, plus symlinks:
   ```
   sudo ln -sf /usr/lib/i386-linux-gnu/libmpfr.so.6 /usr/lib/i386-linux-gnu/libmpfr.so.4
   sudo ln -sf /usr/lib/i386-linux-gnu/libgmp.so.10 /usr/lib/i386-linux-gnu/libgmp.so.3
   ```
3. `export PATH=<toolchain>/usr/bin:$PATH`, then `make build/<target>`.

WSL quirk: the 32-bit toolchain cannot read sources on Windows drvfs (`/mnt/c`) and fails with "Value too large for defined data type". The busybox build already works around this by staging in `$(HOME)/.miicam-build` (override with `MIICAM_NATIVEDIR`); expect the same error for other packages if you build the full image directly in WSL instead of in the container.

## Git / CI quirks

- `tools/bin/*`, `tools/lib/*.so`, and `sdcard/firmware/bin/*` are gitignored, yet some binaries are committed. CI force-adds them (`git add -f tools/bin/rtspd`, etc.). If you edit C code and rebuild, commit the binary with `git add -f tools/bin/<name>`, not plain `git add`.
- `codespace` is the active working branch (this checkout is on `codespace`; `master` is not checked out locally). It holds all CI workflows, vs `master` which has fewer. Workflows present on `codespace`: `build-rtspd.yml` (auto-triggers on push to `tools/rtsp_server/**`/`Makefile` AND `workflow_dispatch`, builds `rtspd`/`rtspd-v5`/`rtsp_audio_in`, force-adds `rtspd2MP`/`rtspd`/`rtspd-v5`/`rtspd2MP00`/`rtsp_audio_in`), `build-libs.yml` (auto-triggers on push for `tools/lib/**`, `tools/utils/**`, `Makefile`, force-adds `tools/lib/*.so` + `tools/bin/*`), `build-onvif.yml`, `build-aac-play.yml`, `opencode.yml` (responds to `/oc` or `/opencode` in PR comments).
- `build-aac-play.yml` works around the `aac_player.c` filename bug by compiling `aac_play.c` directly with `$(TOOLCHAIN_PREFIX)-gcc` instead of using `make build/aac_play`.

## Deploying to a camera

- Camera mounts the SD at `/tmp/sd`; binaries live at `/tmp/sd/firmware/bin`. `tools/dev/helpers.sh` (sourced inside the build container) provides `rb <target>` and `upload_rtsp`/`upload_binary`/`upload_libs` via `scp root@$CAMERA_HOSTNAME`; requires `tools/dev/host.cfg` (gitignored, template at `host.cfg.example`) with the camera hostname.
- `sdcard/config.cfg` is the camera config and is generated (not hand-edited) by `sdcard/firmware/scripts/update/configupdate`; the target device reads `/tmp/sd/config.cfg`.
